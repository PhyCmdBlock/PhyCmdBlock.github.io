week2 lesson2

  • #define 符号常量标识符 符号常量
    会把标识符出现的地方全部替换成后面的符号常量。

  • C++ 标识符的命名规则：

  1. 由字母或下划线开头
  2. 由数字、字母、下划线组成
  3. 大小写敏感
  4. 长度 <=32,超过 32 位相同编译器会认为这是一个变量。这个行为不同的编译器不一样
  5. 标识符不能与已有关键字重复

  • &是取址符，可以显示变量在内存中的起始地址位置。

  • vs2026 里面可以用中文作为变量名，但是兼容性差（gcc 就报错），不允许使用

  • auto 类型由变量初值自动决定变量类型，在涉及很复杂变量名的时候方便，但本课程禁用。

  • int a = b = c = 10; 是一句错误的赋值

  • int c, b, a = b = c = 10; 是一句正确的赋值：这体现了编译器思维，从左到右，见过就是有，没见过就是没有

  • 变量不赋初值在 vs2026 里报错，gcc 里警告，并使用不可预知的值（内存残留内容，没打扫）。

  • 数据溢出在 C++ 里不当作是一种错误

  • 不同类型变量互相赋值：
    同型有无符号整数互赋：机内二进制表示没有损失，一模一样，但由于两种编码不一样，表示的意义不一样。大概就是 long long 的 0 和正数部分那些数字互转没问题，但 long long 负数部分、unsigned long long 长出来那一部分是会互相转化的，产生意义的变化。其他的有无符号整型也是一样的道理。
    相关代码理解：

  • 不同长度整型互转：
    短到长，一般都不会出问题，就是补位数就好了
    有符号整数就补符号位，正数 0 补 0,负数补 1,能使得补码数值不变。
    无符号整数就补 0.
    但这里会发现一个问题，如果一个有符号的短类型负数转到无符号的长类型上，由于补的符号位是 1,前面全是 1,而无符号类型用的不是补码，多的 1 是把他当数值解读的，此时会导致数值突然膨胀。

  • 长到短是事故多发地，因为要舍弃部分数据了，此时编译器也会警告。
    采用的方法也很简单，高位不管多少，全部扔掉，低位不管怎么编码，都直接赋上去。

  • 浮点单双精度互转：
    很显然不可能像整数那样暴力转，而是有对应的，指数对指数，尾数对尾数。float 到 double 里一定不会出现问题。但是 double 到 float，如果 double 的指数部分大过 float 的承载能力，可能出现显示为 inf 的情况，会报警告（C4305 “初始化”: 从“double”到“float”截断），如果只是尾数大过 float 的承载能力，很简单，降低精度，裁掉后面的尾数。

  • char 就是一个 1 字节整型，可以参与运算。
    int a = 'A' 补齐了 24bit 的 0 的。
    char a = 65 去了 24bit 的高位。

  • ‘a’-32 这是一个可以的操作。这里相当于是 1 字节整型变量-4 字节整型变量。具体规则之后说。

  • C++ 原生没有字符串变量，用字符数组来模拟。
    #include<string> 是一个封装罢了

  • 常量的这个 const 先写后写无所谓
    const double pi = 3.14; 和 double const pi = 3.14; 一样

  • 运算符按照操作对象分为一元二元三元运算符，也叫一目二目三目运算符。所以为什么 ?: 被叫作三目运算符，是因为 C++ 里只有他一个三目运算符，就直接拿类型名字称呼了。

  • 一个级别的运算符只可能是同一个结合性。
